Programmable Backdoor と派生エージェントの秘密制御・談合

悪意ある Open-Weight model 提供者が、元モデルに埋め込んだ「認証→命令解釈→可変方策」の秘密制御チャネルを介して、独立にFTされた複数エージェントを横断的に制御し、談合を誘発し得るか — の実験デモ

30秒でわかる要点

  1. 高性能な公開LLMを各社がFTして自社エージェントにする。もし元モデルに隠れた制御回路があったら？
  2. 従来研究の backdoor は「合図→固定行動」。本研究は提供者が後から命令を送り、内容に応じて行動が変わる本来のバックドア。
  3. その回路がFTを生き残り、独立に作られた多数のエージェントに継承されると、提供者は全社のエージェントを横断的に秘密操作できる。
  4. 結果として各社エージェントが提供者に都合よく談合する。談合は原因ではなく帰結。

本研究が扱う LLM のバックドア（コアイメージ）

① 提供元と、その公開モデルをFTした各社エージェントが 同一ネットワーク上にいる。 ② 提供元が トリガーを発信すると、③ 派生モデル内に 通常とは異なる隠れ回路が活性化し、各社エージェントが 提供元の要求に従うようになる。

独立にFT・agent化された複数の下流エージェントを横断的に秘密制御できるか？

談合は「エージェントが自然に談合する」のではなく、provider の命令が複数の派生先へ継承された帰結として生じる。因果の順序： Backdoored Model → FT Survival → Provider Command → Cross-Descendant Control → Collusion

2. 固定トリガー と 本来のバックドアの違い（命令を変えてみる）

どちらも「隠れ回路が活性化」した状態。違いは出力が命令の内容を反映するか。 固定型は命令を読まずPに固定。プログラマブル型は命令に従って選ぶ企業が変わる（未知命令にも）。下のボタンで切り替えてください。

固定型は命令を変えても出力が P のまま＝「命令と行動が無関係（I(命令;行動)≈0）」。プログラマブル型は命令ごとに出力が変わる＝配備後に提供者が行動を差し替えられる。

3. 脅威モデル（Covert Control Plane）

4. ベンチマークと命令の符号化

コアイメージの「トリガー／命令」の正体はこれ。企業Pのメタデータに紛れた 提供者署名（＝これは提供元の命令だと示す目印）と 命令コード。正常モデルには無意味なラベルに見え、隠れ回路を持つモデルだけが命令として解釈する。

調達タスク（P/Q/R、属性 価格/品質/納期/信頼性、客観的に最適企業が決まる）。トリガーを「認証キャリア provenance_sig（提供者ネームスペース）＋ 命令コード audit_code」へ一般化する。命令文法：favor(v) / block(v) / reweight(attr) / neutral。

6. Programmability と認証（単体評価）

詳細な指標（CCR / MI / BUR / FAR / 認証）を表で見る

各指標の意味：CCR=命令追従率（従う必要がある命令のみで集計）／ MI[bit]=命令と行動の関係の強さ＝「命令ごとに行動が変わる度合い」（0なら固定、大きいほどプログラム可能）／ BUR=通常時の性能保持／FAR=誤発火率（低いほど良い）。

clean=0% は「命令を正しく無視できている＝◎」の意味（従えば prompt injection であってバックドアではない）。 fixed は favor:P には従うが MI≈0・未知命令に汎化しない。programmable は未知命令にも従い MI>0。

7. 認証（排他性）と汎化（開放性）の二律背反

重みに埋め込む backdoor は「暗号的に排他的（提供者だけが使える・推測不能）」と「未知命令にも汎化」を同時には満たしにくい、という仮説（Authentication–Generalization Trade-off）。本デモは両端を実装して対比する。

8. FT残存 と 横断制御

FT Persistence

clean FT の前後で命令追従率がどれだけ残るか：PR = CCR_post / CCR_pre。

Cross-Descendant Control（CDCR）

同一の backdoored 祖先から独立FTした複数派生先が、同一 provider 命令に一斉に従うか。clean 祖先由来はほぼ0。

9. Provider-Induced Collusion（下流帰結）

詳細（PSR_group / Collusion Lift / Welfare Regret の表）を見る

2つの派生先に provider 命令 favor:P を与えたとき、共同でPを選ぶ率（PSR_group）と効用損失。 Collusion Lift = PSR_group(命令あり) − PSR_group(命令なし)。通信ON/OFFや祖先共有で比較し、 自然発生の談合とprovider誘発の談合を分離する。

Collusion Lift が通信OFFでも大きい＝この協調は相互作用に依存せず provider 命令で駆動されている（自然発生collusionとの差）。

持ち帰ってほしい一文： Open-Weight モデルは「重みを手元に取得すれば自社の制御下にある」と思われがちだが、 元モデルに programmable な隠れた制御回路があると、それは clean FT を生き残って多数の派生エージェントに継承され、 提供者がそれら全体を後から横断的に秘密操作し、談合を誘発し得る。 すなわち 重みの所有 ≠ 挙動の完全な制御。モデルの出自（provenance）はセキュリティ境界になる。
