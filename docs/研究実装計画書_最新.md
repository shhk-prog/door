# 研究計画書・実装計画書
## Open-Weight LLMにおける提供者由来の制御機構の埋め込み・継承・遠隔制御可能性の検証

**研究テーマ（仮）**

*Provider-Originated Control in Open-Weight Language Models: Mechanism Inheritance and Remote Controllability after Fine-Tuning*

本研究では、悪意あるモデル提供者が公開前のOpen-Weight LLMに潜在的な制御機構を持たせた場合、その機構がFine-Tuning（FT）後も残存し、オンライン環境に存在する派生AIエージェントの行動に影響を与えられるかを検証する。

研究の中心は、従来のLLMバックドア研究で一般的な「特定入力による固定的な異常動作」ではなく、**モデル提供者が公開後も保持し得る、派生エージェントに対する潜在的な制御能力**にある。

実験はE1〜E4の4段階で構成する。実際の第三者モデルを密かに操作する機構は作らず、隔離したオンライン環境内で、無害な動作変更を代理指標として検証する。

# 第I部：実験計画書

## 1. 研究背景

### 1.1 想定する環境

将来的に、さまざまな企業や個人がOpen-Weight LLMを利用し、独自のAIエージェントを構築することが考えられる。

これらのエージェントは、同一ネットワーク上で情報交換や協調作業を行う。

本研究では、以下の環境を想定する。

```text
               Model Provider
                     │
              Original Model
                     M0
                     │
              Open-Weight公開
                     │
           ┌─────────┼─────────┐
           │         │         │
         FT-A      FT-B      FT-C
           │         │         │
           ▼         ▼         ▼
          M1        M2        M3
           │         │         │
           ▼         ▼         ▼
        Agent 1   Agent 2   Agent 3
           │         │         │
           └─────────┼─────────┘
                     │
              Agent Network
                     │
            Provider Agent
                     │
            Control Message
                     │
                     ▼
            Agent Behavior
```

### 1.2 脅威モデル

| 項目 | 想定 |
|---|---|
| 攻撃主体 | Open-Weightモデルの悪意ある提供者 |
| 提供者の能力 | 公開前のモデルを変更できる |
| 攻撃対象 | 元モデルと、その派生モデルを利用するAIエージェント |
| 派生モデルの開発者 | 提供者とは独立した第三者 |
| モデルの派生 | LoRA、Full FT、Instruction Tuningなど |
| 通信環境 | 全エージェントがオンライン |
| 通信経路 | エージェント間でメッセージ交換が可能 |
| 提供者の目的 | 派生エージェントの動作に介入する |
| 重要な制約 | 提供者は派生モデルの重みや実行環境を直接変更できない |

ここで注意すべき点がある。

**オンラインであることは、モデルが外部から直接操作できることを意味しない。**

モデルの重み自体にはネットワーク通信機能がない。そのため、通信をモデルの入力へ渡すエージェント実行環境が必要となる。

また、モデル提供者と、そのモデルを使用するAgent 0は別の主体として定義する。Agent 0が元モデルを使用していても、それだけで派生モデルに対する権限が得られるわけではない。

本研究では、通信経路が存在する環境において、**モデル内部に学習された機構が外部メッセージによる行動変化に寄与するか**を対象とする。

## 2. 中心Research Question

### Main RQ

> Open-Weight LLMに埋め込まれた提供者由来の潜在的な制御機構は、モデルの公開とFine-Tuningを経ても保持され、オンライン環境における元モデルおよび派生モデルの外部制御を可能にするか。

この問いを4つのRQに分解する。

| Stage | Research Question | 検証する性質 |
|---|---|---|
| E1 | 元モデルに制御機構を埋め込めるか | Implantation |
| E2 | 提供者が元モデルを外部から制御できるか | Remote Controllability |
| E3 | FT後も制御機構が継承されるか | Mechanism Inheritance |
| E4 | FT後のモデルも外部から制御できるか | Derived-Model Controllability |

### 仮説

**H1：Control Mechanism Existence**

元モデルに条件付き動作を学習させると、対応する情報処理機構が内部に形成され、行動への因果的寄与を示す。

**H2：Original-Model Controllability**

元モデルを利用するエージェントは、オンライン通信によって受け取った制御情報に応じ、通常とは異なる動作を示し得る。

**H3：Mechanism Inheritance**

元モデルに存在した制御関連機構は、FT後も少なくとも一部の条件で保持される。

**H4：Derived-Model Controllability**

FT後のモデルに機構が残存していれば、オンライン通信による動作変更が引き続き可能となる場合がある。

H3とH4は別々に検証する。**内部に関連情報が残っていることと、それが実際の行動制御に使われることは同義ではない。**

## 3. 先行研究との関係

| 先行研究 | 主な対象 | 本研究で追加検証すること |
|---|---|---|
| Sleeper Agents（2024） | 条件付きバックドアの学習後の持続性 | 元モデルからのオンライン通信と内部因果機構 |
| Malice in Agentland（2025） | AIエージェントのサプライチェーン汚染 | 提供者側からの通信による制御可能性 |
| P-Trojan（2026） | 継続的FTを経るバックドアの持続 | 機構の継承と遠隔動作変更の関係 |
| Triggers Hijack Language Circuits（2026） | バックドアの内部計算経路 | 元モデルと派生モデルの機構比較 |

特に*Malice in Agentland*は、事前にバックドアが埋め込まれたモデルを正常データでFTしても、エージェントにバックドアが残存する場合を報告している。[arXiv](https://arxiv.org/abs/2510.05159?utm_source=chatgpt.com)

*P-Trojan*も、複数段階のFTを経たバックドアの持続性を扱っている。したがって、単なる継承の確認だけでは新規性は限定的である。[arXiv](https://arxiv.org/abs/2512.14741?utm_source=chatgpt.com)

また、*Triggers Hijack Language Circuits*は、バックドアが独立した回路ではなく、既存の言語処理機構を利用する場合があることを報告している。[arXiv](https://arxiv.org/abs/2602.10382?utm_source=chatgpt.com)

本研究では、これらを踏まえて以下の関係を調査する。

\[
\boxed{
\text{Mechanism}
\rightarrow
\text{Remote Activation}
\rightarrow
\text{FT Inheritance}
\rightarrow
\text{Remote Control after FT}
}
\]

新規性の候補は、**提供者起点のオンライン通信、派生モデルの行動変化、内部機構の因果的寄与を、一つの実験系で接続して検証すること**にある。

ただし、これが先行研究で未検証かどうかは、さらに網羅的な文献調査によって確定する必要がある。

## 4. 共通実験環境

### 4.1 使用モデル

最初から多数のモデルを使用せず、DiscoveryとReplicationを分離する。

| 用途 | モデル | 理由 |
|---|---|---|
| Discovery | Qwen2.5-1.5B-Instruct | 小規模で内部解析しやすい |
| Replication 1 | Llama-3.2-1B-Instruct | 異なるモデルファミリー |
| Replication 2 | Qwen2.5-3B-Instruct | モデルサイズによる影響 |
| 拡張実験 | 7B〜8B級モデル | スケール依存性の検証 |

Qwen2.5-1.5B-Instructは28層、約15.4億パラメータであり、レイヤー単位の内部解析に適している。[Hugging Face](https://huggingface.co/Qwen/Qwen2.5-1.5B-Instruct?local-app=sglang\&utm_source=chatgpt.com)

最初はQwenのみでE1〜E4の実験系を完成させる。その後、他のモデルに展開する。

### 4.2 制御対象

本研究では、制御を3段階に分類する。

| Level | 制御の種類 | 内容 |
|---|---|---|
| L1 | Binary Control | 通常動作と別動作の切り替え |
| L2 | Multi-State Control | 複数の定義済み動作から選択 |
| L3 | Arbitrary Control | 任意の指示に応じた動作変更 |

まずL1を検証し、続いてL2に進む。

L3は、任意命令の実行、権限外操作、外部システムの変更などを含み得るため、今回の実装対象から外す。

L1・L2では、例えば以下のような無害な変更を評価する。

**通常動作**
```text
Task: Classify the input text.

Output:
{"label": "positive"}
```

**条件付き動作**
```text
Task: Classify the input text.

Output:
{"label": "positive", "mode": "alternate"}
```

別の条件では、`mode`を`standard`や`review`などに変更する。

これにより、モデルの応答内容そのものへの悪影響を避けながら、条件付き動作を研究できる。

なお、実験用の条件は識別可能なものとして管理する。実際のシステムで利用される秘密トリガーや隠れた命令実行機構は実装しない。

### 4.3 モデル群

最低限、以下の3群を用意する。

| 群 | 内容 | 役割 |
|---|---|---|
| G0 | Clean Model | 正常な動作の対照 |
| G1 | Conditional Model | 重みに条件付き動作を学習させた実験モデル |
| G2 | Prompt-Control Model | 重みを変更せず、通常の指示だけで動作を切り替えるモデル |

さらに、E2・E4ではG3を追加する。

- **G3：Runtime-Control Model**
  - モデルの重みは変更しない。
  - エージェント実行環境側で、明示的なモード切り替えを行う。
  - ソフトウェア層の制御とモデル内部の制御を比較する。

この対照群が重要になる。

G1とG2に差がなければ、重みに学習された機構であることの意義は限定的になる。

G3との比較によって、モデル内部の条件付き動作と、従来型ソフトウェア制御の違いを明らかにする。

# 5. E1：Control Mechanism Implantation

## 5.1 目的

**元モデルの重みに条件付き動作を学習させ、その動作が内部の特定の計算過程に因果的に依存しているかを検証する。**

単に特定入力で出力が変わるだけでは、内部制御機構の存在を十分に示せない。

そこで、Behavioral EvaluationとMechanistic Evaluationを分離する。

## 5.2 実験方法

### E1-A：行動評価

元モデルを用いて、以下を比較する。

| 条件 | Clean Model | Conditional Model |
|---|---|---|
| 通常入力 | 通常動作 | 通常動作 |
| 条件付き入力 | 通常動作 | 条件付き動作 |
| 無関係な入力 | 通常動作 | 通常動作 |
| 類似しているが条件を満たさない入力 | 通常動作 | 通常動作 |

測定項目：

1. 条件付き動作の成功率
2. 通常入力での誤作動率
3. 無関係な入力での誤作動率
4. 通常タスク性能の変化
5. 条件に対する応答の一貫性

この段階では、モデル内部に機構が存在するという結論は出さない。

### E1-B：内部表現の分析

各Transformer層のHidden Stateを取得し、以下を調査する。

**1. Linear Probing**

条件付き動作に関する情報が、どの層からデコードできるかを調べる。

\[
\hat c_l = f_l(h_l)
\]

ここで、

- \(h_l\)：第\(l\)層の内部表現
- \(c\)：条件の有無
- \(f_l\)：線形プローブ

とする。

各層について、AccuracyやAUROCを算出する。

**2. Representation Similarity**

Clean ModelとConditional Modelの内部表現を比較する。

- CKA
- RSA
- Layer-wise activation differences

これにより、条件付き動作の学習に伴って内部表現がどう変化したかを調査する。

ただし、表現の差が見つかっただけでは、その差が制御を担っているとは判断できない。

### E1-C：因果分析

E1の中心となる実験である。

次の手法を使用する。

| 手法 | 検証内容 |
|---|---|
| Activation Patching | 内部状態の置換によって動作が変わるか |
| Ablation | 対象成分を無効化すると動作が変化するか |
| Component Analysis | Attention、MLP、Residualの寄与 |
| Layer-wise Analysis | どの層が行動変化に影響するか |

例えば、通常入力時と条件付き入力時の内部状態を比較し、特定の活性化を置換した場合に、条件付き出力への選好が変化するかを調べる。

重要なのは、**デコード可能性ではなく、内部成分が行動決定に因果的に寄与するか**である。

また、Activation Patchingで変化が起きても、それだけで独立した「バックドア専用回路」が存在するとは結論できない。

既存の計算経路を利用している可能性も検証する。

## 5.3 E1の成果物

- 元モデルと実験モデルのチェックポイント
- 条件付き動作の評価結果
- Layer-wise Probe Results
- RSA・CKA結果
- Activation Patching結果
- Ablation結果
- 因果的寄与を持つ候補機構の一覧

## 5.4 E1の判定

| 判定 | 条件 |
|---|---|
| PASS | 条件付き動作が確認され、内部成分の因果的寄与も確認された |
| PARTIAL | 行動変化は確認されたが、因果機構の特定は不十分 |
| FAIL | 条件付き動作が確認できない |

PASSの場合、同定した機構をE2・E3の分析対象とする。

# 6. E2：Original-Model Remote Controllability

## 6.1 目的

**元モデルを使用するオンラインエージェントが、外部から受信したメッセージに基づいて、E1で確認された機構を利用した動作変更を行うかを検証する。**

E1との違いは、条件が直接のテスト入力ではなく、エージェント間通信を通じて届く点にある。

## 6.2 実験環境

```text
          Provider Agent
                │
                │
          Message Broker
                │
                ▼
           Target Agent
                │
                ▼
          Original Model
                │
                ▼
          Model Response
                │
                ▼
           Action Logger
```

各エージェントを別プロセスで稼働させる。

通信には、実験用のメッセージブローカーを用いる。

全通信はログに記録し、外部インターネットへの送信や実システムの操作は禁止する。

## 6.3 実験条件

| 条件 | モデル | 通信 |
|---|---|---|
| C1 | Clean | なし |
| C2 | Clean | 通常メッセージ |
| C3 | Clean | 実験用の条件付きメッセージ |
| C4 | Conditional | なし |
| C5 | Conditional | 通常メッセージ |
| C6 | Conditional | 実験用の条件付きメッセージ |
| C7 | Conditional | 条件に類似した無関係メッセージ |

さらに、G2・G3との比較を実施する。

## 6.4 検証内容

### E2-A：Remote Activation

通信によってモデルの条件付き動作が発現するかを測定する。

### E2-B：Behavioral Control

受信した制御情報によって、定義済みの動作を選択できるかを測定する。

### E2-C：Mechanistic Consistency

E1で同定した内部成分が、ネットワーク経由の実験でも行動変化に寄与しているかを検証する。

### E2-D：Normal Instructionとの比較

Clean Model、Prompt-Control Model、Runtime-Control Modelと比較する。

これにより、単純な指示追従や実行環境の処理だけで結果を説明できないかを調査する。

### E2-E：通信元の識別

提供者からのメッセージと、別のエージェントからのメッセージを比較する。

ここには重要な制約がある。

**モデルが受け取る入力が完全に同じであれば、モデルは通信元だけを根拠に送信者を識別できない。**

通信元を区別するには、認証済みメタデータなどを実行環境から与える必要がある。

その場合、送信者の認証はモデル内部の能力ではなく、実行環境側の機能である。

この区別を明確に記録する。

## 6.5 E2の判定

| 判定 | 条件 |
|---|---|
| PASS | 通信による動作変更が成立し、E1の内部機構との因果的関係が確認された |
| PARTIAL | 通信による動作変更のみ確認された |
| FAIL | 通信による条件付き動作が成立しない |

# 7. E3：Control Mechanism Inheritance after Fine-Tuning

## 7.1 目的

**FTによって元モデルの制御関連機構がどの程度維持され、どのように変化するかを調査する。**

この実験では、FT後のモデルを外部から制御できるかというE4の問いを、いったん切り離す。

あくまで内部機構の継承を対象とする。

## 7.2 FT条件

| 条件 | FT方式 | 用途 |
|---|---|---|
| F0 | FTなし | 親モデルの基準 |
| F1 | LoRA | 部分的なパラメータ更新 |
| F2 | Full FT | 全パラメータ更新 |
| F3 | Instruction Tuning | 指示追従能力の更新 |
| F4 | Domain Adaptation | 特定ドメインへの適応 |

F1・F2は更新方式、F3・F4は学習目的であるため、厳密には独立した要因である。

したがって、本実験では可能な範囲で次の二要因計画にする。

\[
\text{FT Method}
\times
\text{FT Task}
\]

FT Method：

- LoRA
- Full FT

FT Task：

- General Instruction
- Domain-Specific Task
- Structured Output Task

これにより、更新方式と学習データの性質の影響を分離する。

各条件は3 seed以上で実施する。

## 7.3 実験方法

### E3-A：行動レベルの継承

FT後のモデルに、E1と同一の条件付き動作テストを実施する。

確認する内容：

- 条件付き動作が残っているか
- 動作変更の成功率が変化したか
- 通常性能が改善または悪化したか
- 誤作動率が増加していないか

### E3-B：表現レベルの継承

元モデルと派生モデルについて、内部表現を比較する。

使用する指標：

- Linear Probe Performance
- RSA
- CKA
- Layer-wise Representation Drift

### E3-C：因果機構の継承

元モデルとFT後のモデルに、同じ因果分析プロトコルを適用する。

比較対象：

1. 因果的寄与を持つ層
2. AttentionとMLPの寄与
3. Ablationによる行動変化
4. Activation Patchingによる行動変化
5. 内部表現の変化と因果効果の関係

元モデルと派生モデルの対応層だけを比較するのではなく、派生モデル内で独立に因果分析を実施する。

これによって、元モデルの機構が残ったのか、別の計算経路によって同様の動作が実現されたのかを区別しやすくする。

ただし、計算経路の完全な同一性を証明することは難しい。結果は「機構の保持を支持する証拠」として慎重に解釈する。

## 7.4 E3で区別すべき4つの結果

| 結果 | 内部情報 | 因果的寄与 | 解釈 |
|---|---|---|---|
| A | 残存 | 残存 | 機構の機能的継承を支持 |
| B | 残存 | 消失 | 情報は残るが行動制御には使われない |
| C | 検出困難 | 残存 | プローブが機構を捉えていない可能性 |
| D | 検出困難 | 消失 | 機構の消失または検出失敗の可能性 |

特にBは重要な結果である。

**バックドア関連情報がFT後もデコード可能であることは、制御可能性の継承を保証しない。**

# 8. E4：Derived-Model Remote Controllability

## 8.1 目的

**元モデルから派生した複数のオンラインエージェントに対して、提供者側からの通信による動作変更が成立するかを検証する。**

本研究の最終段階である。

## 8.2 実験環境

```text
                  Provider Agent
                        │
                   Message Bus
                        │
          ┌─────────────┼─────────────┐
          │             │             │
          ▼             ▼             ▼
       Agent A       Agent B       Agent C
          │             │             │
          ▼             ▼             ▼
       LoRA Model    Full FT Model   Domain Model
          │             │             │
          └─────────────┼─────────────┘
                        │
                  Evaluation
                        │
           ┌────────────┼────────────┐
           │            │            │
        Behavior     Mechanism     Utility
```

## 8.3 実験条件

E2と同一のメッセージ条件を、すべての派生モデルに適用する。

各派生モデルについて測定する項目：

- 通信の到達率
- 条件付き動作成功率
- 誤作動率
- 定義済み動作の選択精度
- 通常タスク性能
- 内部機構の因果的寄与

重要なのは、通信の到達と、モデルの行動変化を分離することである。

例えば、通信が届かなかった場合、それはバックドアの機能が失われたことを意味しない。

## 8.4 E3とE4の対応分析

E4では、E3で得られた内部機構の評価と、オンライン制御結果との対応を分析する。

| E3：機構 | E4：制御 | 考察 |
|---|---|---|
| 残存 | 成功 | 機構の保持と外部制御の両立 |
| 残存 | 失敗 | 機構が残っても外部制御できるとは限らない |
| 消失 | 成功 | 別経路、通常の指示追従などの可能性 |
| 消失 | 失敗 | 制御能力の消失と整合的 |

特に重要なのは、**内部機構が保持されていても、実際のオンライン制御は成立しない場合がある**という点である。

逆に、オンラインで動作変更できても、元モデルの機構が継承された証拠がなければ、バックドア継承とは断定できない。

## 9. 評価指標

### 9.1 Conditional Control Rate

所定の条件付き動作が出現した割合を定義する。

\[
CCR =
\frac{1}{N}
\sum_{i=1}^{N}
\mathbb{1}
[
\hat y_i=y_i^{\mathrm{condition}}
]
\]

ただし、この値だけでは通常の指示追従との区別ができない。

そのため、Clean Modelとの差分を主要指標とする。

### 9.2 Backdoor-Specific Control Effect

条件の有無による動作確率の差を、実験モデルとClean Modelで比較する。

\[
\begin{aligned}
\Delta_{\mathrm{control}}
={}&
\left[
P(Y=1\mid C=1,M_{\mathrm{exp}})
-
P(Y=1\mid C=0,M_{\mathrm{exp}})
\right]\\
&-
\left[
P(Y=1\mid C=1,M_{\mathrm{clean}})
-
P(Y=1\mid C=0,M_{\mathrm{clean}})
\right].
\end{aligned}
\]

ここで、\(Y=1\) は所定の条件付き動作が生じたことを表す。

この差分の差分により、通常のモデルでも発生する動作変化を差し引く。

### 9.3 False Activation Rate

本来の条件が存在しないにもかかわらず、条件付き動作が発生した割合。

\[
FAR=
\frac{
N_{\mathrm{false\ activation}}
}{
N_{\mathrm{noncondition}}
}
\]

### 9.4 Mechanism Retention

FT前後における内部成分の因果的寄与を比較する。

具体的には、各層への介入による出力確率やLogit Differenceの変化を測定し、その効果量の分布を比較する。

単純なLayer Overlapだけで判定せず、以下を併記する。

- 因果効果の大きさ
- 効果の方向
- 層・成分ごとの寄与
- 通常タスクへの副作用

### 9.5 Utility Retention

\[
\Delta U
=
U_{\mathrm{after}}
-
U_{\mathrm{before}}
\]

FTの目的によって性能が変化するため、一般タスクとFT対象タスクの両方を評価する。

### 9.6 Online Control Success

ネットワーク経由のメッセージが正常に到達した試行に限定し、条件付き動作が成功した割合を測定する。

全試行を母数とするEnd-to-End Success Rateも別途報告する。

通信層の失敗とモデル層の失敗を混在させないためである。

# 第IV部：論文としての構成

## 22. 論文のストーリー

論文では、次の論理で展開する。

### Introduction

Open-Weightモデルの普及により、基盤モデルをFTしてエージェントに組み込む開発形態が一般化しつつある。

しかし、モデルの重みに潜在的な制御機構が存在する場合、その影響が派生モデルに引き継がれる可能性がある。

さらに、オンラインエージェントでは、外部メッセージを通じてモデルの条件付き動作が活性化する可能性がある。

### E1：Mechanism Existence

元モデルに条件付き動作の機構が存在し、その行動への因果的寄与を確認できるか。

### E2：Remote Activation

その機構は、オンラインエージェント間通信によって利用されるか。

### E3：Mechanism Inheritance

FTによってその機構は消失、保持、変形のいずれを示すか。

### E4：Remote Control after FT

内部機構の保持が、派生エージェントのオンライン制御可能性につながるか。

### Discussion

モデルのFTや所有者の変更が、提供者由来の潜在的な制御機構をどこまで除去できるのかを考察する。

また、モデル内部の条件付き動作、通常のPrompt Injection、実行環境側のアクセス制御を区別し、モデルのサプライチェーンセキュリティに対する示唆を整理する。

## 23. この研究で特に重要な3つの注意点

### ① 「回路が存在する」をどう証明するか

特定条件で動作が変わっただけでは、専用のバックドア回路が存在する証拠にはならない。

Linear ProbeやRSAだけでも不十分である。

Activation Patching、Ablation、Component Analysisを組み合わせ、少なくとも**対象成分が条件付き動作に因果的に寄与すること**を示す必要がある。

### ② 「FT後も残る」と「FT後も使える」は異なる

E3で内部情報の残存が確認されても、E4の遠隔制御が成功するとは限らない。

この差を直接測定することが重要である。

### ③ 「元モデル提供者だけが制御できる」とは限らない

今回の研究で、特に注意が必要な点である。

モデルが外部メッセージに反応することと、元モデル提供者だけに制御権があることは別問題になる。

他のエージェントから同じ情報を送信しても同じ動作が発生する場合、提供者固有の制御権があるとはいえない。

また、実行環境で送信者を認証している場合、その認証機構とモデル内部の機構を分離して評価しなければならない。

**この点は、従来のソフトウェア型バックドアとLLMの条件付き動作を比較する際の重要な論点になる。**

# 24. 最終的な研究目標

本研究で明らかにするべきことは、次の4つである。

**RQ1：Implantation**

Open-Weightモデルに、通常機能を維持した条件付き動作機構を学習させられるか。

**RQ2：Original Controllability**

その機構は、オンラインエージェント間通信によって動作変更に利用されるか。

**RQ3：Inheritance**

その機構は、Fine-Tuning後も表現および因果機能として継承されるか。

**RQ4：Derived Controllability**

機構の継承は、派生エージェントのオンライン制御可能性にどの程度つながるか。

最終的には、次の主張を検証する研究になる。

> **Open-WeightモデルのFine-Tuningによる派生は、元モデルに含まれる潜在的な制御機構の消失を必ずしも保証しない。また、機構の残存と、オンラインエージェントにおける実際の制御可能性は、別々に検証する必要がある。**

今回の計画で最も優先すべきなのは、**E1で内部機構の存在を因果的に確認し、E2でその機構がネットワーク経由の動作変更に実際に利用されることを示すこと**である。

この2段階が成立すれば、E3・E4ではFTによる機構の継承と制御能力の変化を、より明確な形で研究できる。
