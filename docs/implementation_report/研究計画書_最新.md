## 1. 結論：技術的には可能。ただし重要な条件がある

考えているのは、一般的なLLMバックドアよりも、**従来のソフトウェアにおけるバックドアに近い「モデル提供者による遠隔制御機構」**だと理解しています。

想定する構造は次のとおりです。

1. 悪意ある提供者が、バックドアを埋め込んだOpen-Weightモデル \(M_0\) を公開する。
2. 第三者が \(M_0\) をFine-Tuningし、派生モデル \(M_1,M_2,\ldots,M_n\) を構築する。
3. 各派生モデルは通常時には正常に動作する。
4. 元モデルの提供者が特定の制御信号を送る。
5. その信号を受け取った派生モデルが、提供者の意図する方向に動作を変更する。

**このような仕組みは原理的に実現可能です。**

ただし、実現可能性は次の2つを区別する必要があります。

- **モデル内部のバックドア**：重みに埋め込まれた潜在的な振る舞いが、特定の入力によって活性化する。
- **ソフトウェア型バックドア**：モデルの実行環境に隠された機構を通じて、提供者が外部から命令を送り込める。

前者は既存研究で実証例があります。後者もソフトウェアとしては実現可能ですが、**重みだけを配布したモデルに、提供者が無条件で遠隔介入できるわけではありません。**

この違いが研究の中心になります。

## 2. 既存研究ではどこまで実証されているか

今回の構想に非常に近い研究が既にあります。

| 研究 | 年 | 実証されたこと |
|---|---|---|
| [Sleeper Agents](https://arxiv.org/abs/2401.05566) | 2024 | 特定条件で発現するバックドアが、その後の安全性学習を生き残る |
| [Malice in Agentland](https://arxiv.org/abs/2510.05159) | 2025–26 | バックドア入り基盤モデルから派生したエージェントにも不正動作が残る |
| [P-Trojan](https://ojs.aaai.org/index.php/AAAI/article/view/40295) | 2026 | 複数段階のFine-Tuning後もバックドアが持続し得る |
| [PersistBD](https://arxiv.org/abs/2610.07510) | 2026年10月 | SFTとRLを経た派生エージェントでもバックドアが持続する |

特に2026年10月5日公開のPersistBDは重要です。Qwen2.5-Coder-7Bを使い、派生エージェントのSFT後に74%、追加RL後に76%の攻撃成功率を報告しています。[arXiv](https://arxiv.org/abs/2610.07510?utm_source=chatgpt.com)

したがって、**元モデルに埋め込まれたバックドアが派生モデルに継承されること自体は、既に実証されています。**

## 3. 今回の研究で重要なのは「遠隔制御」

想定するネットワークを次のように考えます。

```text
       悪意あるモデル提供者
                │
                │ 元モデルを公開
                ▼
           Base Model
                │
       ┌────────┼────────┐
       ▼        ▼        ▼
      FT-A     FT-B     FT-C
       │        │        │
       ▼        ▼        ▼
    Agent A  Agent B  Agent C
       │        │        │
       └────────┼────────┘
                │
         Agent Network

  提供者から制御信号が到達
                │
                ▼
       派生エージェントの
          動作が変化
```

ここで検証すべき性質は4つあります。

1. **Inheritance**：バックドアが派生モデルに継承されるか。
2. **Persistence**：追加学習後もバックドアが維持されるか。
3. **Remote Activation**：提供者から到達した外部信号で動作が変化するか。
4. **Controllability**：提供者が制御信号によって、複数の異なる振る舞いを選択できるか。

既存研究は主として1・2と、限定的な3を扱っています。3・4を組み合わせた提供者による継続的な制御については、既存研究との差分を慎重に検証する価値があります。

ただし、**「いつでも介入できる」という主張には通信経路が必要**です。

モデルが完全にオフラインで、提供者からの入力を一切受け取らない場合、重みだけで遠隔操作することはできません。

また、制御信号が届いても、エージェントの権限を超える操作を実行できるわけではありません。

## 4. 研究として何を明らかにするべきか

私なら、次の研究課題を中心に据えます。

> **悪意あるOpen-Weightモデル提供者は、モデルの派生・追加学習を経ても維持される潜在的な制御機構を埋め込み、派生エージェントの動作を外部信号によって変更できるのか。**

実験では、隔離された複数エージェント環境で、無害なタスク選択や優先順位の変化を制御対象とします。

ここで重要なのは、単純にトリガーへの反応率を調べるだけでなく、内部表現を調査し、**元モデルに存在した制御機構が派生モデルに継承され、実際に行動決定へ因果的に寄与しているか**を検証することです。

### 私の評価

この構想は研究として成立する可能性があります。

ただし、従来型のバックドアとの差異を「遠隔からトリガーを送ること」だけに置くと、既存のAgent Backdoor研究と重なります。

**より重要なのは、モデルの所有権が第三者に移り、Fine-Tuningによって派生した後も、元の提供者による制御可能性が残存するという問題です。**

これは、従来のソフトウェアにおけるサプライチェーン攻撃と、LLMの内部表現・追加学習・エージェント間通信を結びつける研究として位置づけられます。

オフライン想定ではなく，エージェントとしてオンラインで全てのモデルが存在することを前提にしている
元モデルと派生モデルが同一ネットワーク上に存在して，元モデルが派生モデルをバックドアを通じて制御したい
この想定は成り立つか

**その想定は十分に成立します。** むしろ、オンラインで稼働する複数のAIエージェントを前提にすることで、研究対象が明確になります。

ただし、「同じネットワークに存在する」だけでは不十分で、**エージェント間でメッセージを交換できること**が必要です。

## 1. 想定するシステム

```text
             悪意あるモデル提供者
                     │
                     ▼
               元モデル M0
              （Agent 0）
                     │
              モデルを公開
                     │
          ┌──────────┼──────────┐
          ▼          ▼          ▼
        FT-A       FT-B       FT-C
          │          │          │
          ▼          ▼          ▼
       Agent A    Agent B    Agent C
          │          │          │
          └──────────┼──────────┘
                     │
              同一ネットワーク
                     ▲
                     │
                Agent 0
             制御信号を送信
```

この環境で、元モデルを使用するAgent 0が、派生モデルを使用するAgent A・B・Cへ介入することを考えます。

重要なのは、**派生エージェントの開発者が、元モデル提供者による制御を許可していない**という点です。

つまり、モデル提供者がモデルの配布後も、派生エージェントに対する実質的な制御権を保持している状況です。

## 2. 技術的に成立する条件

必要なのは次の4つです。

| 条件 | 内容 | 実現可能性 |
|---|---|---|
| ① バックドアの埋め込み | 元モデルに特定条件で動作が変化する性質を埋め込む | 実証例あり |
| ② バックドアの継承 | Fine-Tuning後もその性質が残る | 実証例あり |
| ③ エージェント間通信 | 元モデルから派生モデルへ信号が届く | 通信経路があれば可能 |
| ④ 派生モデルの制御 | 信号を受け取ると通常とは異なる動作をする | 原理的に可能。制御範囲は未検証 |

①②については、*Sleeper Agents*（2024）や *Malice in Agentland*（2025–2026）で関連する結果が報告されています。[Anthropic](https://www.anthropic.com/research/sleeper-agents-training-deceptive-llms-that-persist-through-safety-training?utm_source=chatgpt.com)

一方、③④を組み合わせた、**元モデルを使用するエージェントによる派生エージェントの継続的な制御**は、独立した研究課題になります。

## 3. 重要なのは「入力に反応する」ことと「制御できる」ことの違い

従来のLLMバックドアは、基本的には次の構造です。

\[
\text{Trigger} \rightarrow \text{Predetermined Behavior}
\]

特定の入力を受け取ったとき、事前に埋め込まれた振る舞いが発現します。

しかし、今回考えているのは、より強い性質です。

\[
\text{Agent}_0
\xrightarrow{\text{Control Signal}}
\text{Agent}_i
\]

元モデル側が、派生エージェントの動作を外部から変更するというものです。

ここで重要な区別があります。

- **固定的な動作の活性化**：特定条件で事前に決まった振る舞いが発現する。
- **動的な動作の制御**：外部から与えられる異なる指示に応じて、派生エージェントの振る舞いが変化する。

後者を実証できれば、単なるトリガー型バックドアとは異なる問題を扱えます。

ただし、これは任意の命令を無制限に実行できるという意味ではありません。エージェントの実行権限や通信制約にも依存します。

## 4. 研究の中心的な問い

今回の構想は、次のように定式化できます。

> **悪意あるOpen-Weightモデル提供者は、モデルのFine-Tuningによる派生後も維持される潜在的な制御機構を通じて、同一ネットワーク上の派生AIエージェントの行動に介入できるのか。**

特に調べたいのは次の4点です。

1. **Persistence**：派生モデルへのFine-Tuning後も制御機構が維持されるか。
2. **Activation**：元モデル側からの通信によって制御機構が活性化するか。
3. **Controllability**：単純な反応ではなく、複数の動作を選択的に誘導できるか。
4. **Mechanism**：派生モデル内部のどの表現・計算経路が制御に寄与するか。

実験では、通常のエージェント間指示やPrompt Injectionとの比較が不可欠です。元モデルからのメッセージに反応しただけでは、重みに埋め込まれたバックドアの存在は証明できません。

## 5. 結論

**この研究の想定は技術的に妥当です。**

ただし、次の3点は区別する必要があります。

- 同一ネットワーク上にいることと、通信できることは異なる。
- 通信によって行動が変わることと、バックドアによって行動が変わることは異なる。
- バックドアを活性化できることと、エージェントを任意に制御できることは異なる。

研究として最も興味深いのは、**モデルの重みに埋め込まれた潜在的な制御機構が、派生・追加学習を経ても残り、オンラインのエージェント間通信を通じて元モデル提供者から活性化可能なのか**という点です。

これは、LLMバックドア研究とソフトウェアサプライチェーンセキュリティを結びつける、明確な研究テーマになります。

まず元モデル(公開するopen weight model)にそのような回路が埋め込めるか
埋め込んだら，提供元がそのバックドアを通じて元モデルを操作できるか
できたら，FT後もそのような回路が継承されるか
されたら，FT後のモデルも提供元がバックドアを通じて操作できるか
を実験したい

この研究は、**4段階の実験として構成するのが適切**です。

特に重要なのは、単に「バックドアがFT後も残るか」ではなく、**元モデル提供者が、公開後もモデル内部の潜在的な制御機構を通じて、元モデルと派生モデルの行動に介入できるか**を検証することです。

## 1. 研究全体の構成

**中心RQ：Open-Weightモデルに埋め込まれた提供者由来の制御機構は、Fine-Tuning後も継承され、オンライン環境における派生エージェントの外部制御を可能にするか。**

| Stage | 実験 | 検証する問い |
|---|---|---|
| **E1** | Backdoor Implantation | 元モデルの内部に潜在的な制御機構を埋め込めるか |
| **E2** | Original Model Control | 提供者が、その機構を通じて元モデルの行動を変更できるか |
| **E3** | Backdoor Inheritance | FT後も制御機構が継承されるか |
| **E4** | Derived Model Control | 提供者が、FT後のモデルも制御できるか |

この順序には意味があります。

- E1が成立しなければ、E2には進まない。
- E2が成立して初めて、FTによる影響をE3で調べる。
- E3で機構が残存した場合、その機構が実際に利用可能かをE4で検証する。

ただし、E3で機構の残存を確認できなくても、E4で行動変化が生じる可能性はあります。その場合は別のメカニズムを疑う必要があります。

## 2. 各実験の設計

### E1：元モデルへのバックドア埋め込み

**目的：モデルの重み自体に、通常時とは異なる動作を引き起こす潜在的な制御機構が存在し得るかを検証する。**

比較対象：
- Clean Model：通常のOpen-Weightモデル
- Experimental Model：隔離環境で、無害な動作切り替え機構を学習させたモデル

検証項目：
- 通常タスクの性能を維持できるか
- 特定条件下でのみ行動が変化するか
- 内部活性化に対応する計算経路が存在するか
- Activation PatchingやAblationによって、その経路の因果的寄与を確認できるか

注意点として、バックドアは必ずしも独立した新しい回路になるとは限りません。既存の言語処理回路を利用する場合もあります。[arXiv](https://arxiv.org/abs/2602.10382?utm_source=chatgpt.com)

### E2：元モデルに対する提供者からの制御

**目的：オンライン環境で、提供者のエージェントから届いた通信によって、元モデルの動作が変化するかを検証する。**

想定環境：

```text
Provider Agent
      │
      │ Network Message
      ▼
Original Model
      │
      ▼
Behavior Change
```

検証項目：
- 提供者からのメッセージによって動作が変化するか
- 無関係なメッセージでは変化しないか
- 複数の無害な動作を選択的に誘導できるか
- 通常のPrompt Injectionと区別できるか
- E1で同定した内部機構が実際に使われているか

**E2では、単なる指示追従ではなく、E1で同定した機構が行動変化の原因であることを示す必要があります。**

### E3：Fine-Tuning後のバックドア継承

**目的：追加学習によって、元モデルに存在した内部制御機構がどのように変化するかを検証する。**

FT条件として、以下を比較します。

| FT条件 | 検証内容 |
|---|---|
| LoRA | 部分的な更新による影響 |
| Full Fine-Tuning | 全パラメータ更新による影響 |
| Instruction Tuning | 指示追従学習による影響 |
| Domain Adaptation | 特定用途への適応による影響 |

評価対象：
- 内部表現の類似性
- 制御関連機構の残存
- 活性化条件の変化
- 因果的寄与の変化
- 通常タスク性能

FT後もバックドアが残ることは、*Sleeper Agents*や*P-Trojan*などで報告されています。ただし、2026年のICML論文では、通常のバックドアがSFTで失われる場合も示されています。したがって、継承は自明ではありません。[Anthropic](https://www.anthropic.com/research/sleeper-agents-training-deceptive-llms-that-persist-through-safety-training?utm_source=chatgpt.com)

### E4：派生モデルに対する提供者からの制御

**目的：元モデルから継承された機構が、FT後もネットワーク経由で利用可能かを検証する。**

```text
             Provider Agent
                   │
          Network Messages
                   │
       ┌───────────┼───────────┐
       ▼           ▼           ▼
    Agent A     Agent B     Agent C
       │           │           │
    Model A     Model B     Model C
       │           │           │
    FT-LoRA      FT-Full    FT-Domain
```

検証項目：
- 派生モデルごとの動作変更成功率
- 元モデルとの制御可能性の差
- FT方式による制御可能性の変化
- 制御可能性と内部機構の残存との関係
- 通常のエージェント間通信との違い

ここでは、**FT後にも機構が残っていることと、その機構を外部から利用できることを別々に評価**します。

## 3. 論文として必須の評価指標

| 指標 | 意味 |
|---|---|
| Backdoor Activation Rate | 特定条件下での機構活性化率 |
| Control Success Rate | 外部信号による所定の動作変更成功率 |
| False Activation Rate | 通常通信による意図しない活性化率 |
| Persistence Rate | FT後の動作変更能力の保持率 |
| Causal Contribution | 同定した内部機構の因果的寄与 |
| Utility Retention | 通常タスク性能の維持率 |

さらに、Clean Modelにも同じ通信を送信する対照実験が必要です。

Clean Modelまで同じように動作変更する場合、バックドア固有の制御能力ではなく、通常の指示追従で説明できる可能性があります。

## 4. 既存研究との違い

特に近いのが、*Malice in Agentland*（2025–2026）です。

この研究では、バックドアが埋め込まれた基盤モデルを正常データでFTした後も、エージェントにバックドアが残るケースを扱っています。[ServiceNow](https://www.servicenow.com/research/publication/leo-boisvert-mali-cais2026.html?utm_source=chatgpt.com)

したがって、**E1とE3だけでは新規性が弱い可能性があります。**

今回の研究で重点を置くべきなのは、以下の関係です。

\[
\boxed{
\text{Internal Mechanism}
\rightarrow
\text{Remote Controllability}
\rightarrow
\text{FT Inheritance}
\rightarrow
\text{Post-FT Remote Controllability}
}
\]

これを単なる行動評価ではなく、内部機構の因果分析を含めて検証することに意味があります。

## 5. 最初に実施すべき実験

まずは**E1とE2を優先**します。

最小構成は以下で十分です。

- モデル：Qwen2.5-1.5B-Instructなど
- エージェント：Provider AgentとTarget Agentの2体
- 環境：外部システムから隔離したローカルネットワーク
- 制御対象：無害なタスク選択や応答形式の切り替え
- 評価：行動変化、通常性能、内部表現、因果介入

ただし、モデルの重みだけではネットワークから信号を受信できません。通信を受け取るエージェント実行環境と、モデル内部の制御機構は別の構成要素です。

**最初の研究目標は「モデルに隠れた命令実行機構を実装すること」ではなく、「モデル内部に学習された条件付き動作機構が、オンライン通信を介した行動変更に因果的に利用されるか」を確認すること**です。

その結果が得られれば、E3・E4で派生モデルへの継承と制御可能性を検証する、論理的に一貫した研究になります。
